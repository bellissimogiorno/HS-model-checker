# Executable HBB3 examples

These examples accompany Murdoch J. Gabbay and Isaac Sheff, *Heterogeneous trust in reliable broadcast via modal logic and history structures*, draft 7 November 2026. The protocol is Figure 11, p. 56, Definition 8.2.1, p. 55; its correctness statements are Figure 12, p. 56, Theorem 8.2.3, p. 57. Agreement is proved in Proposition 8.3.1, p. 57; Liveness 2 in Proposition 8.4.5, p. 59; Liveness 1 in Proposition 8.5.1, pp. 59–60. Every executable rule carries its own source comment.

The editable names `CorrSeq`, `CorrPast`, `CorrSymm`, and `CorrTran` map to the paper’s dotted-equality rules (≐seq), (≐⇓), (≐symm), and (≐tran). HBB3 writes `vote(l,v)` and `deliver(l,v)` with learner first and broadcast value second. This differs from the three-argument delivery event in HBB1 and HBB2.

Each document contains its exact finite DAG, quorum bases, facts, editable protocol rules, dynamic full `ThyLive`, and all three unmodified conditional correctness claims. The cases in [hbb3-cases.json](../examples/hbb3-cases.json) search all predicate interpretations of that fixed DAG with positive facts pinned. They do not search larger histories or prove an unbounded theorem. Silent † tuples record observations; they are not extra protocol actions. The full KnowledgeDia and KnowledgeBox schemes remain selected and are regenerated from each model’s complete quorum-intersection families.

The browser chooser starts each removal example with the named rule already omitted. Run the preset to observe that weakening, choose **Keep all axioms** for the full-theory comparison, and choose **Use example defaults** to restore the omission. These are explicit run selections, not changes to the declarations below. Plain Markdown imports and generic CLI runs retain every source declaration unless `--drop NAME` is supplied. The deliberately incorrect replacement/control documents keep their distinct expected outcomes; they are not converted into artificial correctness counterexamples.

A **No model** result means no interpretation in the requested scope satisfies the retained axioms. Its properties are **Not tested**, not proved. A failed correctness claim requires an axiom-satisfying model and a false property in that same model.

The matrix includes full-theory no-model comparators for the three missing-progress prefixes. Each omission model’s literal interpretation violates exactly the named removed rule; all its other axioms, including every full `ThyLive` instance, pass. The safety examples explicitly add `NoLive`, which fixes their scenario and makes no claim about progress. Every failed canonical implication is checked at one concrete participant, history, and learner/value binding with its premise and trigger true and its conclusion false. “Holds; absent” exposes vacuity rather than treating it as an exercised success.

The 3twined example uses quorums `{p,r}`, `{p,q}`, `{q,r}`. Their pairwise intersections are nonempty, while their triple intersection is empty. The live participants p and q vote for b with different values; both forward vote rules still hold because both participants do cast those votes. No homogeneous b-vote quorum forms, so no b-delivery is required by Deliver!. This isolates the missing triple intersection used in Section 8.4, pp. 58–59. It is distinct from the valid alternative condition in Remark 8.6.2(4), p. 61.

The Vote'! example keeps 3twined and all correlation laws. Learner a trusts `{p}`, while b trusts `{p,q}`. Two live participants echo distinct proposed values, so b has no homogeneous echo quorum. An a-vote exists and a delivers, but b never votes. Only Vote'! rejects that history. The current paper’s `everytime corr` antecedent is deliberate (footnote 54, p. 57); this example does not replace it by a current-time test.

The incorrect-equivalence pair implements Remark 8.6.4, p. 61, literally: `forall l,m. corr(l,m) <-> dia[l,m] seq` replaces both CorrSeq and CorrPast. In the shared DAG, L, M, N trust `{p,a}`, `{p,a,b}`, `{p,b}`. All triple intersections contain p. Participant p forks, while a and b remain sequential. Thus the L–M and M–N sequential intersections hold but L–N does not. Empty correlation satisfies the actual theory; the equivalence forces the two first pairs and rejects the third, contradicting retained CorrTran. The baseline’s extra `Incorrect correlation equivalence` diagnostic is therefore false, while all three canonical claims hold vacuously. The replacement has no model on the same DAG, so none of those claims is tested there. This is a semantic design failure through overconstraint, not a refutation of a correctness theorem. The motivating side-choosing discussion is Remark 8.1.1(2), pp. 54–55.

Run `node demo.mjs --suite hbb3 --output reports/hbb3-examples` to reproduce the matrix and save model and counterexample certificates. The output directory contains a checked report and independently replayable evidence. Run `node --test test/hbb3-examples.test.mjs` for the regression: it checks canonical formulas, exact retained rules, all-interpretation synthesis, complete theory checks, nonvacuous false conditionals, and independent certificate replay. The 20-tuple 3twined case explicitly sets `maxCompilationNodes: 1000000` in the matrix; this changes the finite resource budget, not the semantic search scope.
